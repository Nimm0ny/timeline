# 编年 Agent 友好笔记方向

## 产品目标

编年以普通 Markdown 笔记为核心。用户和 Agent 在同一篇笔记上共同订正、优化格式、扩写内容，并能接续彼此的修改。

笔记是双方共同维护的内容。Agent 能读取用户授权的笔记、提出有范围的建议、说明进度。用户能看到具体差异，决定接受、拒绝或继续调整。未确认的建议不直接覆盖正文。

## 产品边界

- 笔记正文保持普通 Markdown，创建和编辑以笔记为中心。
- 移除思维导图、自由画布、图关系浏览、反向链接和自动链接解析。
- 保留普通笔记列表、标签、属性和现有 collection views。
- 既有图形笔记和关系数据属于用户数据。先预览迁移结果，在数据库副本上核对，并保留原始内容的恢复方式。
- 应用启动时不自动迁移或删除用户数据。真实数据库迁移须由用户单独触发。

本方案对“知识图谱能力”的默认解释包括图形编辑和笔记关系功能。若用户只想移除思维导图和画布，可以收窄范围并保留普通笔记链接。

## Feature Map 和可复现操作

CLI 的主要发现结果是 Feature Map。它描述用户能完成的能力、真实入口、适用状态、前置条件、数据范围、权限、持久化结果、失败恢复和关联操作。Feature Map 是 UI、API 和 CLI 共同遵守的能力目录，不是测试报告，也不是证据文件清单。

发现入口可沿用 Sikao 的 feature list、describe、guide、scenarios、steps 和 run 命令族。Feature Map 由注册信息提供，不从 Vue 组件树或 API 路由名称猜能力。具体参数格式留给实现阶段。

每项能力把真实 UI 入口、正式 API schema、数据状态所有者和具名操作连在一起。可重跑的场景定义稳定步骤、输入、前置状态、实际操作、可观察断言、持久化回读和清理范围。相同步骤既供 CLI 执行，也供开发者和 Agent 发现、复用。未知能力或无法判定的状态须明确返回，不猜命令、不伪报成功。

CLI 以 Feature Map 为主要发现输出，并提供按需读取能力说明和操作场景的入口。一次场景运行返回简短 JSON 结果，包括 feature、scenario、通过或失败、失败原因和 nextAction。截图、trace、完整日志等证据文件默认不生成；只有场景明确需要视觉判断或用户要求时才采集。服务健康、页面打开和单次观察都不能代替业务场景通过。

最终 CLI 面向整个编年应用，除用户能力场景外，还提供受限的 API 诊断和固定开发验证入口；各入口报告实际检查范围，服务可连接或构建通过不能替代未执行的业务验证。

## 共写体验

用户从一篇 Markdown 笔记开始。短句订正、格式优化和扩写可针对选中内容发起。整篇或多轮任务在 Agent 面板里继续。

Agent 的每项修改都绑定笔记身份和来源版本。界面显示正在处理、建议差异和建议基于的版本。用户可逐项接受、拒绝或继续给出要求。若用户在此期间编辑了原文，旧建议标记为过期，不能覆盖新内容。

建议采用混合交互。选区操作处理局部修改，Agent 面板处理整篇任务和多轮对话。视觉上沿用编年现有简洁浅色体系。原型比较了选区工具、Agent 侧栏和混合协作三种路径，混合模式是当前推荐方向。

原型只确认桌面布局能承载这条写作流程。它没有证明任务派发、实时进度、冲突处理或持久化已经可用。

## 前后端 API 和数据契约

首次契约审阅时，多个 API 路由接收通用 dict，Vue API 客户端没有集中声明请求和响应类型；useApi.js 将服务端 detail 转成普通 Error，也没有稳定错误码和下一步操作。Note 有 updatedAt，但没有用于并发写入的版本条件。这些问题是本方向的审阅基线；实际实现状态以当前 API 路由、OpenAPI 契约和 CLI 诊断结果为准。

方向上，FastAPI 的正式 schema 是全应用 API 的契约来源。Vue API 客户端和 Agent CLI 都按同一契约发送请求、解析稳定错误码和可执行 nextAction，并处理回执。Feature Map 引用这些 schema，不复制另一套字段定义。

笔记写入绑定笔记身份、来源版本和幂等操作身份。Agent 先读取授权范围内的笔记和版本，再提交有边界的建议。服务端拒绝过期建议。用户确认后才写入。请求结果未知时，调用方读取原操作并回读笔记，不盲目重试。

CLI、Vue 和后端都使用具名操作。CLI 不直接写 SQLite，不开放任意 HTTP 代理或页面脚本。前端使用可访问的控件名称和稳定的笔记身份，使真实操作可定位、可观察。保存中、已保存、冲突、建议过期和失败状态由产品状态驱动，不另造测试专用状态。

## Agent 接入

用户从界面创建任务。Feature Map 指定该任务允许访问的笔记和操作。已连接的 Agent 领取任务后读取冻结的笔记版本，发送进度并提交建议。界面把任务状态和建议显示给用户。没有 Agent 连接时显示等待状态。

建议先接入外部 Agent。编年负责任务、授权、笔记版本、进度、建议和用户确认后的保存。编年不托管模型或凭据。真实模型调用、凭据读取和费用操作须另行确认授权。

沿用 Sikao 的 Feature Map 和按需发现方式，不照搬其大型证据框架。操作结果必须能用同一输入和前置条件重新执行。Agent session 只能访问登记范围内的笔记；接受或拒绝建议属于用户操作，Agent 不能代替用户确认。

## 迁移原则

思维导图可转成带层级的 Markdown。画布可转成按卡片组织的 Markdown，并以普通文本保留连接信息。原始 JSON 和关系记录保留在可导出的归档中。

迁移先给出 dry-run 预览，再在数据库副本上验证笔记数量、身份、正文和归档回读。任何无法安全转换的内容都保留原件并明确报错。当前用户数据库、备份和上传资源不在本方案的自动操作范围内。

## 推进顺序

1. 定义 Feature Map，连接用户能力、真实 UI 入口、API schema、数据前置和可重跑操作场景。
2. 统一 Vue、FastAPI 和 CLI 使用的笔记请求、响应、版本、错误与回读契约。
3. 提供 Feature Map 发现、具名操作和真实场景运行能力。证据文件按需生成。
4. 明确图形笔记和关系数据的归档与转换方式，再移除对应功能。
5. 加入版本保护的 Agent 任务和建议协议，以及外部 Agent 桥接。
6. 实现选区修改、差异审阅、进度呈现和冲突保护的共写界面。

这些阶段只表达依赖方向，不规定文件清单、PR 划分或逐项测试命令。实施时再按实际调用方和观察到的行为拆分。

## 可观察的完成状态

- Agent 能通过 CLI 发现应用操作，启动或连接服务，并验证一次笔记创建、编辑和重新读取。
- Feature Map 能把用户能力对应到真实入口、正式 API schema、可重跑场景和失败恢复方式。CLI 的操作结果包含可判定的运行状态，证据文件按需生成。
- 普通笔记保留 Markdown、标签、属性和集合视图。图形与关系功能从产品入口退场，原有内容仍可恢复。
- 用户可以针对选中文本或整篇笔记发起订正、格式优化或扩写，看到 Agent 进度和具体差异。
- 接受建议后，正文和版本更新且重新读取一致。拒绝建议不改正文。过期建议不能覆盖用户的新修改。
- 未连接 Agent、API 错误、冲突和未知写入结果都有清楚状态及可操作的恢复路径。

## 尚待用户确认的方向

- “移除知识图谱”是否包含 wikilinks、反向链接和手动笔记关联。当前建议全部移除，并保留正文原文和关系归档。
- Agent 是否通过外部运行时接入。当前建议先提供外部 Agent 桥接，不在编年内托管模型。
- 是否采用混合共写界面。当前推荐使用原型中的选区工具加 Agent 侧栏。
